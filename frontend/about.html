The Internet & Climate Change

hidden carbon cost.

Every byte transferred across the internet consumes energy. EcoWeb Auditor makes that invisible cost visible — element by element.

The Scale
A problem as big as aviation.

Root Causes
What makes a website carbon-heavy?

Every HTTP request, every kilobyte downloaded, and every render-blocking script demands energy — from your server, from the global network, and from the device in your visitor's hand.

Unoptimised Images
Images typically account for 50–60% of a page's total weight. A single uncompressed hero image in PNG format can exceed 5 MB — the equivalent of hundreds of text pages. Converting to WebP or AVIF typically reduces size by 60–85% with no visible quality loss.
Bloated JavaScript
Large vendor bundles are the second biggest contributor to page weight. Modern bundlers often ship 3× more code than the initial route needs. Tree-shaking, code-splitting, and removing unused dependencies can reduce bundle size by 40–70%.
Unsubsetted Fonts
Web fonts loaded without subsetting carry thousands of characters your page never uses. Subsetting a font to your actual character set reduces it by 60–80%. Always use WOFF2 format and add font-display: swap.
Unpurged CSS
Utility-first CSS frameworks like Tailwind ship hundreds of kilobytes of unused rules in development mode. A production build with PurgeCSS or Tailwind's built-in purge reduces a 300 KB stylesheet to under 10 KB.
The Energy Chain

Origin Server
Web servers consume electricity 24/7. Every request wakes CPUs and reads from disks. Larger files mean more compute time.

Data travels through undersea cables, routers, and exchange points — all electricity-powered. The SWD model estimates 0.81 kWh per gigabyte transferred globally.
3

Parsing JavaScript, decoding images, and rendering layouts all tax the device's CPU and GPU — draining batteries and generating heat. Heavier pages demand more device energy.

The Calculation Method
Sustainable Web Design model.

EcoWeb Auditor uses the peer-reviewed Sustainable Web Design (SWD) model developed by Wholegrain Digital and documented by Tom Greenwood in Sustainable Web Design (A Book Apart, 2021). It is the same methodology used by WebsiteCarbon.com.

CO₂ (g) = ( bytes ÷ 10⁹ ) × 0.81 kWh/GB × 442 gCO₂/kWh
bytes Total data transferred in bytes — sum of all page assets
0.81 kWh/GB Estimated energy to transfer 1 gigabyte across the global internet
442 gCO₂/kWh Global average carbon intensity of electricity (2023 figure)
Result Estimated grams of CO₂ produced per single page visit

Developer Guide
10 ways to reduce your website's carbon footprint.

Each of these changes is also a performance improvement — faster pages and greener pages are the same page.

01
Convert images to WebP or AVIF
WebP reduces file sizes by 25–35% vs JPEG; AVIF by 50%+. Use picture with srcset to serve the best format per browser. Tools: Squoosh, ImageOptim, Sharp (Node.js).
02
Lazy-load below-the-fold assets
Add loading="lazy" to all <img> and <iframe> elements not in the initial viewport. This defers transfers entirely until the user scrolls — assets never viewed are never downloaded.
03
Enable Brotli compression
Brotli compresses HTML, CSS, and JS 15–25% better than Gzip. Configure it in your web server or CDN. Verify with curl -H "Accept-Encoding: br" -I <url> and check for content-encoding: br.
04
Purge unused CSS
Utility frameworks (Tailwind, Bootstrap) include thousands of unused rules in development. Run PurgeCSS or enable Tailwind's built-in purge in production. A 300 KB stylesheet can shrink to under 8 KB.
05
Tree-shake and code-split JavaScript
Import only the functions you use. Use dynamic import() to load route-specific bundles on demand. Audit third-party dependencies at bundlephobia.com before adding them.
06
Subset web fonts
Use glyphhanger or FontSquirrel to generate a font file containing only the Unicode ranges your page actually uses. Combine with font-display: swap to prevent invisible text during load.
07
Use a CDN with edge caching
Serving assets from a CDN node geographically close to the user reduces transfer distance, network hops, and latency — all of which translate directly to lower energy consumption. Cloudflare, Fastly, and AWS CloudFront offer generous free tiers.
08
Set long-lived cache headers
Use Cache-Control: max-age=31536000, immutable on versioned static assets. Returning visitors download nothing — the most sustainable byte is the one never transferred.
09
Prefer SVG over raster for UI icons
An SVG icon library weighs 8–15 KB in total. The same icons as PNG sprites can be 10–20× larger and cannot scale without blurring. Inline critical SVGs directly in HTML to eliminate HTTP requests.
10
Choose a green hosting provider
Check your host at thegreenwebfoundation.org. Providers that run on 100% renewable energy (Hetzner, OVH, GreenGeeks) can cut the carbon intensity of your server traffic by up to 95%.
About This Project
A BSc final year artefact.

EcoWeb Auditor was built as the final-year artefact for a BSc (Hons) Software Engineering degree at the University of Bedfordshire (2026). The project was supervised by Ms. Rameesha Kankanamge.

The research motivation arose from a clear gap in the existing tooling landscape: while tools like WebsiteCarbon.com provide useful aggregate scores, they act as "black boxes" — developers receive a grade but no information about which specific elements are responsible.

Primary market research (n = 31 IT and Software Engineering professionals and students) confirmed this gap: 90.3% of respondents stated they would use a tool that breaks down carbon impact at the individual element level.

The technical stack was chosen to reflect modern industry practice: Python + FastAPI for the async scraping backend, PostgreSQL for relational audit storage, and plain HTML/CSS/JavaScript for the frontend to ensure the UI itself remains as lightweight as possible.
